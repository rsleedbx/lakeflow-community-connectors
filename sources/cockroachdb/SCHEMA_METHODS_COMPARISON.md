# Schema Methods Comparison

## Overview

There are two methods in `cockroachdb.py` that work with schemas from Unity Catalog Volumes. They serve **different purposes** and return **different data types**.

## The Two Methods

### 1. `_load_schema_from_volume()` (Metadata)

**Location**: Lines 2884-2948  
**Purpose**: Load table metadata (primary keys, column families)  
**Returns**: Python `dict`  
**Source**: Reads `_schema.json` file

```python
def _load_schema_from_volume(self, volume_path: str, spark=None, dbutils=None) -> dict:
    """Load schema file from Unity Catalog Volume."""
    # Reads: /Volumes/.../path/_schema.json
    # Returns: {"primary_keys": ["id"], "column_families": {...}}
```

**Example Usage**:
```python
# Get primary keys for CDC processing
schema_info = connector._load_schema_from_volume(volume_path)
primary_keys = schema_info.get('primary_keys', [])  # ['ycsb_key']
has_families = schema_info.get('column_families', {})  # {...}
```

**Return Value**:
```python
{
    "primary_keys": ["ycsb_key"],
    "column_families": {
        "fam_0_ycsb_key": ["ycsb_key"],
        "fam_1_field0": ["field0"],
        ...
    }
}
```

**Used By**:
- `load_and_merge_cdc_to_delta()` - Get primary keys for merging
- `analyze_volume_changefeed_files()` - Get primary keys for deduplication
- CDC processing functions - Determine if column family merge is needed

---

### 2. `_get_schema_from_volume()` (Spark Schema)

**Location**: Lines 361-396  
**Purpose**: Infer Spark DataFrame schema (column names and types)  
**Returns**: Spark `StructType`  
**Source**: Reads and infers from data files (`.ndjson` or `.parquet`)

```python
def _get_schema_from_volume(self, table_name: str) -> StructType:
    """Get Spark schema for a table by reading from Unity Catalog Volume files."""
    # Reads: /Volumes/.../path/data_file.ndjson (or .parquet)
    # Returns: StructType([StructField("id", IntegerType()), ...])
```

**Example Usage**:
```python
# Get Spark schema for creating DataFrame
spark_schema = connector._get_schema_from_volume('usertable')
# Returns: StructType with field definitions
print(f"Schema has {len(spark_schema.fields)} columns")
for field in spark_schema.fields:
    print(f"  - {field.name}: {field.dataType}")
```

**Return Value**:
```python
StructType([
    StructField("ycsb_key", StringType(), True),
    StructField("field0", StringType(), True),
    StructField("field1", StringType(), True),
    ...,
    StructField("_cdc_operation", StringType(), True),
    StructField("_cdc_updated", StringType(), True)
])
```

**Used By**:
- `get_table_schema()` in VOLUME mode - Return schema for DataFrame operations

---

## Key Differences

| Aspect | `_load_schema_from_volume()` | `_get_schema_from_volume()` |
|--------|------------------------------|------------------------------|
| **Returns** | Python `dict` | Spark `StructType` |
| **Source File** | `_schema.json` (metadata) | Data files (`.ndjson`, `.parquet`) |
| **Contains** | Primary keys, column families | Column names, data types, nullability |
| **Purpose** | CDC processing metadata | Spark DataFrame schema |
| **File Size** | Small (~1KB) | Any size (samples first file) |
| **Speed** | Very fast (reads small JSON) | Slower (infers from data file) |
| **Always Available?** | No (generated by test_cdc_matrix.sh) | Yes (if data files exist) |
| **Used When** | Processing CDC changes | Creating DataFrames |

## Why Two Methods?

### Different Data Needs

**CDC Processing** needs:
- ✅ Primary keys (for deduplication and merging)
- ✅ Column family info (for fragment merging)
- ❌ Column data types (not needed - Spark infers these)

**DataFrame Operations** need:
- ✅ Column names and types (for schema validation)
- ✅ Nullability info (for DataFrame creation)
- ❌ Primary keys (not part of Spark schema)

### Different File Sources

**`_schema.json`** (Metadata File):
```json
{
  "table": "usertable",
  "primary_keys": ["ycsb_key"],
  "column_families": {
    "fam_0_ycsb_key": ["ycsb_key"],
    "fam_1_field0": ["field0"]
  }
}
```
- Small, fast to read
- Contains CDC-specific metadata
- Generated by `test_cdc_matrix.sh` or changefeed creation
- Not a standard Spark schema

**Data Files** (`.ndjson`, `.parquet`):
```json
{"ycsb_key": "user001", "field0": "value", ...}
{"ycsb_key": "user002", "field0": "value", ...}
```
- Large, slower to read
- Contains actual data with types
- Always present if CDC data exists
- Spark can infer schema from these

## Call Graph

### CDC Processing Flow
```
load_and_merge_cdc_to_delta()
  └─> connector._load_schema_from_volume()
       └─> Returns: {"primary_keys": [...], "column_families": {...}}
            └─> Used for: Deduplication, merging, column family handling
```

### DataFrame Schema Flow
```
connector.get_table_schema()
  └─> (if VOLUME mode) connector._get_schema_from_volume()
       └─> spark.read.json(sample_file)
            └─> Returns: StructType([...])
                 └─> Used for: DataFrame creation, schema validation
```

## Common Misconceptions

### ❌ WRONG: "They're duplicate code"
**Reality**: They serve different purposes and return different types.

### ❌ WRONG: "`_schema.json` contains full Spark schema"
**Reality**: It only contains primary keys and column families, not column types.

### ❌ WRONG: "Should merge them into one method"
**Reality**: They're used in different contexts with different performance requirements.

### ❌ WRONG: "`_get_schema_from_volume()` should read `_schema.json`"
**Reality**: `_schema.json` doesn't have the column type information needed for Spark schemas.

## Best Practices

### When to Use `_load_schema_from_volume()`
```python
# ✅ Getting primary keys for CDC merge
schema_info = connector._load_schema_from_volume(volume_path)
primary_keys = schema_info['primary_keys']

# ✅ Checking if column family merge is needed
has_families = bool(schema_info.get('column_families'))
```

### When to Use `_get_schema_from_volume()`
```python
# ✅ Creating DataFrame with specific schema
spark_schema = connector._get_schema_from_volume('usertable')
df = spark.createDataFrame(data, schema=spark_schema)

# ✅ Validating schema compatibility
expected_schema = connector._get_schema_from_volume('usertable')
assert df.schema == expected_schema
```

### When to Use BOTH
```python
# Get CDC metadata
schema_info = connector._load_schema_from_volume(volume_path)
primary_keys = schema_info['primary_keys']

# Get Spark schema for DataFrame
spark_schema = connector._get_schema_from_volume('usertable')

# Use both for comprehensive processing
df = spark.read.schema(spark_schema).json(file_path)
df_deduplicated = deduplicate_by_keys(df, primary_keys)
```

## Implementation Notes

### Shared Logic

Both methods share:
- `_ensure_spark_and_dbutils()` for Spark/dbutils validation
- `_list_volume_files()` for file listing (indirectly)
- Error handling patterns

### Independent Logic

Each has unique:
- **`_load_schema_from_volume()`**: JSON parsing, error categorization
- **`_get_schema_from_volume()`**: Format detection, schema inference

### No Duplication

The code is **NOT duplicated** because:
1. They read different files (`_schema.json` vs data files)
2. They return different types (`dict` vs `StructType`)
3. They serve different purposes (CDC metadata vs DataFrame schema)
4. They have different performance characteristics

---

## Summary

**Two methods, two purposes:**

| Method | What | Why |
|--------|------|-----|
| `_load_schema_from_volume()` | Metadata (`dict`) | For CDC processing |
| `_get_schema_from_volume()` | Spark schema (`StructType`) | For DataFrame operations |

**Not duplicates** - they're complementary methods that serve different parts of the CDC pipeline.

**When in doubt**: 
- Need primary keys? → `_load_schema_from_volume()`
- Need column types? → `_get_schema_from_volume()`
